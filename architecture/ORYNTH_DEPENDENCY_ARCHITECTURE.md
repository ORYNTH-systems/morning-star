1. Purpose

This document defines the canonical dependency architecture through which an observer locates ORYNTH frameworks, protocols, runtimes, audit systems, applications, and narrative layers.

The dependency architecture prevents downstream artifacts from being mistaken for self-originating or complete representations of ORYNTH.

4. Entry Dependency Rule

An observer need not master the entire ORYNTH ecosystem before engaging a governed object.

However, the observer must identify all dependencies materially necessary to interpret the selected object without false equivalence, boundary loss, or framework identity collapse.

6. Dependency Relation

For governed objects A and B:

DependsOn(A,B)

means that correct reconstruction of A requires declared structure from B.

It does not mean that A and B are the same framework or that B owns every downstream result.
