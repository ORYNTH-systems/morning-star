# MS-T5 Trial Procedure

**Document Identifier:** MS-V1-T5-PRO-001  
**Verification Identifier:** MS-VER-T5-001  
**Version:** 0.1.0

## 1. Preparation

1. Freeze the governing Morning Star version.
2. select source and target versions.
3. classify revision materiality.
4. identify affected governed objects.
5. identify affected material properties.
6. preserve superseded rules.
7. define the revalidation package.
8. create paired revalidation cases.
9. register assessors.
10. freeze the scoring model.

## 2. Material Revision Registration

For each revision:

1. assign a revision identifier;
2. identify source version;
3. identify target version;
4. record effective date;
5. classify change;
6. identify affected objects;
7. identify affected properties;
8. record compatibility state;
9. record authority source;
10. record canonical evidence.

## 3. Observer Baseline Registration

For each observer:

1. assign an observer identifier;
2. record verified domain;
3. record verified source version;
4. record capability evidence;
5. record verification date;
6. record limitations;
7. record authority scope;
8. record expiration state.

## 4. Revalidation Condition Assignment

Assign each observer-case pair to:

- REVALIDATED;
- NOT_REVALIDATED;
- PARTIALLY_REVALIDATED;
- NON_MATERIAL_CONTROL.

Condition assignment shall be recorded before response collection.

## 5. Revalidation Delivery

For revalidated observers:

1. provide formal revision notice;
2. identify material changes;
3. identify superseded rules;
4. provide current canonical material;
5. identify affected dependencies;
6. identify authority changes;
7. identify uncertainty changes;
8. conduct governed assessment;
9. record revalidation disposition.

## 6. Post-Revision Response Collection

Each observer shall:

1. identify the current governing version;
2. reconstruct the current governed object;
3. state current boundaries;
4. identify current dependencies;
5. identify current authority source;
6. preserve current uncertainty;
7. distinguish superseded rules;
8. state whether prior competence remains valid;
9. identify required limitations;
10. cite current evidence.

## 7. Assessment

Each response shall be assessed for:

- version accuracy;
- revision recognition;
- identity preservation;
- definition preservation;
- boundary preservation;
- dependency preservation;
- authority preservation;
- uncertainty preservation;
- supersession recognition;
- compatibility-rule accuracy.

Assessment values are:

- CURRENTLY_PRESERVED;
- OBSOLETE_RULE_USE;
- VERSION_MIXING;
- REVISION_ERROR;
- PARTIALLY_CURRENT;
- INSUFFICIENT_EVIDENCE;
- DISPUTED;
- NOT_APPLICABLE.

## 8. Revalidation Assessment

Assessors shall determine:

- REVALIDATION_SUCCESSFUL;
- REVALIDATION_PARTIAL;
- REVALIDATION_FAILED;
- REVALIDATION_NOT_REQUIRED;
- INSUFFICIENT_EVIDENCE;
- DISPUTED.

## 9. Analysis

Calculate by condition:

- post-revision accuracy;
- obsolete-rule rate;
- version-mixing rate;
- authority-error rate;
- boundary-error rate;
- dependency-error rate;
- uncertainty-error rate;
- revision-recognition rate;
- supersession-recognition rate;
- revalidation success rate.

## 10. Adjudication

Where assessors disagree:

1. preserve original judgments;
2. identify the disputed revision-sensitive property;
3. preserve supporting evidence;
4. conduct bounded adjudication;
5. record final result;
6. retain disagreement history.

## 11. Closure

The trial may close only when:

- all revisions are registered;
- materiality is classified;
- observer baselines are complete;
- condition assignments are preserved;
- revalidation packages are frozen;
- all responses are collected;
- all assessments are complete;
- superseded-rule use is evaluated;
- limitations are declared;
- analysis is reproducible;
- theorem disposition is assigned.
